# 创新点话术 · 给高管评委的 1 分钟卖点

> **使用方式**：Q&A 阶段被打断时，**先念结论**（一句话），再念证据（三条）。每个创新点都有可现场演的可视证据。

---

## 🏆 主推 · "Self-Aware Security"（安防系统自己知道自己瞎了）

**一句话**：现有安防设备在硬件失效时静默工作；我们让它在被遮挡、被黑屏、被冻结的那一秒主动告诉用户"我看不见了"。

**证据**（按权重排序）：
1. **零硬件成本**：只用摄像头原生 CPU + 边缘端算力，eufy 现有机型（如 eufyCam 3）即可运行。
2. **三个失效模式全覆盖**：`black_screen`（亮度 < 12）/ `obstructed`（边缘密度 < 0.04）/ `frozen`（帧间差 < 2.0）。
3. **场景可现场演**：Demo 第 4 个场景 2 秒内完成"画面从正常到被遮挡"全过程，Health 分从 100 掉到 40、actions 出现 `notify_health`。

**对应竞品短板**（Q&A 备用）：
- Ring / Nest / Arlo：硬件故障只能等用户主动报修，没有"自我诊断"模块。
- 国内萤石 / 360：依赖云端检测，本地失效时延高（> 10s），无法本地即时告警。

---

## 🥈 次推 · "事件聚合打通知疲劳"

**一句话**：把"门口快递"、"家人经过"、"宠物出入"这类应该被忽略的事件聚合掉，只对真正异常的事件做高优通知。

**证据**：
1. **降权规则**：`known_member` -20 / `delivery_like` -20 / `package_left` 需配合 `identity` 异常才触发。
2. **量化收益**：当前 demo 的 family / delivery 场景均输出 risk=0 + actions=log，用户零打扰。

**对应业务价值**（eufy 角度）：
- eufy 定位"无月费"，**用户买断后只能靠体验留人**，通知疲劳会直接导致用户关掉推送。
- 把"误报率"从竞品 90% 降到 < 30%，是 eufy 区别于订阅制产品的关键护城河。

---

## 🥉 第三 · "可解释风险打分"

**一句话**：每条规则对应一个原因字符串，风险分是所有命中规则的加权和——评委追问"为什么是 85 分"可以逐条念出来。

**证据**：
- `risk_reasons: ["unknown", "night", "long_stay", "long_stay_extra", "sensitive_roi", "repeat_approach"]`
- 6 条理由 → 加权 = 85。**任何一条规则改动都只需改 yaml，不动代码。**

**Q&A 防守牌**（为什么不用大模型）：
- 实时性：摄像头本地推理要求 < 200ms / 帧，规则 < 1ms。
- 可解释：监管/合规要求越来越严，模型黑盒风险高。
- 部署成本：eufy 摄像头 RAM 256MB，跑不动 7B 模型。
- 维护：现场调参改 yaml 即可，不用重新训练。

## 🚫 不要主推的（产品/市场原因）

| 创新点                | 不主推的原因                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| 多模态（视觉 + 声音）  | 演示视频里没有麦克风，评委听不到差异；属于方案储备，不是这次交付重点。                                |
| 隐私计算（边缘推理）  | 太"工程话"，高管记不住；只在评委主动追问隐私时一句话带过"全部本地推理，不上传任何帧"。                |
| PTZ 智能跟踪          | 单点能力，非产品创新；演示里能演，但它的价值高度依赖具体硬件型号，不是平台级护城河。                |
